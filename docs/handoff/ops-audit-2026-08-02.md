## 2a. Task B — what was actually done (2026-08-03)

All eight merged to `main`, squash, branches retained. Merge order as prescribed, except that #879/#880/#882/#877 were merged while the #881→#883 stack was still building (they are independent of it, and §2 permits any order among them).

**The stacked-PR trap, hit live.** After #881 merged, #883 still read `base=ops/alert-delivery-log`. Merging it there would have been a silent no-op for production. The fix, in order:

```bash
gh pr edit 883 --base main          # → immediately CONFLICTING/DIRTY
git rebase --onto origin/main <renumber-sha> ops/health-digest-sees-dead-feeds
git push --force-with-lease origin ops/health-digest-sees-dead-feeds
```

The conflict is not a real one: #881 was **squash**-merged, so `main` gained one new commit while #883's branch still carried the two original pre-squash commits. `--onto` drops them and replays only #883's own two commits. Verify before merging — `git diff --stat origin/main..HEAD` should show **only** the health-digest files (`feedHealth.ts`, `health-digest/route.ts`, `feedHealth.test.ts`, `migration-v264-...`), with no trace of `deliveryLog.ts` or `sendAdminMessage.ts`. If those appear, the rebase kept the already-merged commits and the PR will re-apply them.

**This generalises:** any squash-merged stack in this repo needs `--onto`, not a plain `git rebase main`. A plain rebase tries to replay commits whose content is already in `main` and produces conflicts that look like content disagreements but are duplicates.

**Migration numbering is now clean on `main`:** `v260-brand-alias-classifier-variants`, `v261-watchlist-label-variants`, `v262-staleness-exempt-feeds`, `v263-alert-delivery-log`, `v264-feed-health-view` — five files, five distinct numbers, no duplicates. Next free is `v266` per §1.

## 8. Traps this session actually hit

Worth reading before touching this area.

- **Retiring a feed can silently break `is_active`.** `mark_stale_urls`/`mark_stale_ips` deactivate on `last_seen_in_feed`, so a scraper producing zero new rows can still be load-bearing — its periodic touch is what keeps prior findings active. Retiring crt.sh would have dropped 1,726 AU brand-lookalike domains out of the blocklist. **Before retiring or slowing any feed**, run the sole-source query in §0 of the plan doc.
- **`gateOrNotFound()` does not enforce on a statically prerendered route** — the flag is evaluated at build time and baked into HTML. Any route calling it needs `export const dynamic = "force-dynamic"`, enforced by `apps/web/__tests__/featureGateRuntime.test.ts`.
- **`feed_sources.last_success_at` and `consecutive_failures` have NO writer** — NULL/0 on all 68 rows. Use `feed_ingestion_log` for freshness; `feed_sources` is a roster only.
- **A test can pass against a permanently broken loop** if it mocks a state the code cannot produce. `test_cooldown_expires_after_24h` asserted release by mocking a 25h-old head row, which a cron firing every 1.8h can never create. Mock what the live system actually produces.
- **`git stash pop` with no argument pops whatever is on top** — including another session's stash. This tree has 7 pre-existing stashes. Always `git stash push -- <paths>` with `-u` for untracked, and pop by explicit ref.
- **BSD `sed` has no `\S`** — redaction patterns using it silently pass the secret straight through.
